# Feature Development Playbook

## When To Use
Use this playbook when introducing new functionality or significant capability changes.

## Required Steps
1. Understand the user need and repository context.
2. Inspect relevant architecture and model boundaries.
3. Create a scoped plan with validation expectations.
4. Implement the change with minimal structural disruption.
5. Review the change for architectural consistency and risk.
6. Validate the outcome and document the result.

## Validation Checklist
- The feature fits the shared architecture.
- The change does not duplicate existing logic unnecessarily.
- The implementation is documented and testable.

## Expected Output
A clear implementation with documented rationale, validation evidence, and a known rollback path if needed.
