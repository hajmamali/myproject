# Security Review Playbook

## When To Use
Use this playbook when a change affects sensitive paths, trust boundaries, or privileged behavior.

## Required Steps
1. Identify the security-relevant surface area.
2. Review interfaces, data flow, and failure modes.
3. Assess risk and required controls.
4. Validate the change against security expectations.
5. Document residual risk and mitigations.

## Validation Checklist
- Sensitive boundaries remain controlled.
- New logic does not introduce unnecessary privilege or exposure.
- Risks and mitigations are documented.

## Expected Output
A reviewed change with explicit security implications and mitigations.
