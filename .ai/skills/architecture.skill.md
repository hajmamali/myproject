# Architecture Skill

## Purpose
Guide architectural reasoning and ensure changes align with the repository’s core model.

## When To Apply
Use when designing new subsystems, changing boundaries, or evaluating structural impact.

## Required Knowledge
- Repository constitution
- Architecture principles
- Existing project model and graph structures

## Workflow
1. Understand the current architecture.
2. Identify affected boundaries and relationships.
3. Evaluate whether the change improves or weakens the model.
4. Document the rationale and impact.

## Rules
- Preserve architectural coherence.
- Prefer shared abstractions over duplication.
- Make dependencies explicit.

## Forbidden Actions
- Introducing structural shortcuts without review.
- Creating local architecture interpretations.

## Quality Gate
The change is acceptable only if it strengthens clarity, maintainability, and consistency.
