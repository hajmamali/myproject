# Graph Engine Skill

## Purpose
Guide the correct use of semantic, dependency, and call graph analysis for architectural reasoning.

## When To Apply
Use when tracing relationships, understanding propagation, or assessing impact across the repository.

## Required Knowledge
- Graph abstractions
- Architectural boundaries
- Repository model semantics

## Workflow
1. Identify the relevant graph layer.
2. Trace the relationship path.
3. Evaluate the implication for change and risk.
4. Document the impact and any counterexamples.

## Rules
- Use graph representations as the primary source of structural insight.
- Distinguish between direct and indirect relationships.

## Forbidden Actions
- Ignoring graph context when reasoning about impact.
- Overinterpreting low-confidence graph edges.

## Quality Gate
Graph reasoning is complete when the relationship path and implications are explicit.
