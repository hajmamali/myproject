# Documentation Skill

## Purpose
Ensure that repository knowledge remains accurate, useful, and aligned with implementation reality.

## When To Apply
Use when introducing new concepts, changing behavior, or updating architectural guidance.

## Required Knowledge
- Repository context
- Existing documentation structure
- Governance expectations

## Workflow
1. Identify the knowledge gap or drift.
2. Write the documentation in a precise and reusable form.
3. Ensure it reflects current reality and policy.
4. Link it to the relevant architecture or process documents.

## Rules
- Documentation must be explicit, structured, and maintainable.
- Keep examples and guidance concrete.

## Forbidden Actions
- Writing documentation that contradicts the implementation.
- Leaving guidance ambiguous when clarity is required.

## Quality Gate
Documentation is complete when it improves understanding and reduces future misinterpretation.
