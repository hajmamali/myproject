# Glossary

## Purpose
This glossary defines the key terms used in the repository’s governance and architecture framework.

## Scope
It supports contributors and agents in using consistent vocabulary when discussing architectural change.

## Terms
- ProjectModel: The authoritative representation of the repository structure, relationships, and architecture.
- Semantic Graph: A graph representation of meaning, relationships, and conceptual dependencies.
- Dependency Graph: A graph describing structural relationships between components.
- Call Graph: A graph describing execution relationships between functions, methods, or subsystems.
- Detector: A consumer of the shared architecture model that identifies patterns, risks, or anomalies.
- Rule Engine: The logic layer that evaluates architectural constraints and policy conditions.
- Governance: The set of principles, processes, and controls that guide change.
- Architecture Drift: The divergence between intended architecture and the current implementation reality.

## Rules
- Use terms consistently across documentation and implementation.
- Prefer the shared vocabulary over local jargon.

## Expected Behavior
Readers should be able to understand architectural discussions without ambiguity.

## Anti-Patterns
- Defining new terms when existing ones already apply.
- Using vague language for structural concepts.

## Quality Criteria
The glossary should improve clarity and reduce architectural misunderstanding.
