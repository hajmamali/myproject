### SECTION 1 — MUTATION AUTHORITY VERIFICATION (FAILED)
**Claim:** All Cypher routes through `_raw_execute`; raw writes are impossible.
**Reality:** Governance is completely BYPASSABLE.

* **Bypass 1 (`GraphQueryService`):** `mahoun/graph/graph_query_service.py` completely ignores `Neo4jConnection`. It instantiates its own `self.driver.session()` and provides an `execute_write` method that routes direct Cypher to the database, completely bypassing `MutationAuthorizationBoundary`.

  This is a raw, ungoverned destructive mutation executed directly on the driver.

**Verdict:** The boundary is an illusion. Any service that accesses `get_neo4j_driver()` or maintains its own connection pool can circumvent the constitution.

### SECTION 2 — AUTHORIZATION TOKEN FORENSICS (FAILED)
**Claim:** "Cryptographic authorization token."
**Reality:** The "token" is literally a **thread-local boolean**.

* **Forensic Evidence:** In `mutation_boundary.py`, authorization is handled via:
  ```python
  _authorized_write_ctx = threading.local()
  _authorized_write_ctx.active = True
  # execute
  _authorized_write_ctx.active = False
  ```
* **Async Leakage:** Because Python `asyncio` multiplexes coroutines over a single OS thread, if an async function yields control while `_authorized_write_ctx.active = True` (e.g., during network I/O to Neo4j), **any other coroutine running on that same thread will inherit the mutation authority.**
* **Forgery:** Any code anywhere in the runtime can simply import `_authorized_write_ctx` and set it to `True`. There is zero cryptographic signature protecting the boundary context.

**Verdict:** There is no cryptographic token. It is a fragile thread-local flag vulnerable to concurrency leaks and internal forgery.

### SECTION 3 — DETERMINISM REALITY CHECK (FAILED)
**Claim:** Deterministic execution and hashing.
**Reality:** Hashes are **time-dependent**, making them inherently non-deterministic.

* **Forensic Evidence:** In `_make_receipt()` (`mutation_boundary.py`, Line 122):
  ```python
  ts = datetime.now(timezone.utc).isoformat()
  receipt_id = hashlib.sha256(f"{ts}:{entity_id}:{content_hash}".encode()).hexdigest()[:24]
  ```
  Because `receipt_id` includes `ts` (current time), executing the exact same ingestion pipeline twice will yield entirely different receipts. **True determinism does not exist.**
* **Query Generation Order:** `assignments = ", ".join(f"n.{k} = ${k}" for k in cypher_props)` relies on Python's dictionary insertion order. If different pipelines build `node_data` in different property orders, the raw Cypher string changes.

**Verdict:** Provenance tracking is time-coupled. The system fails basic formal verification for determinism.

### SECTION 6 — GOVERNANCE IMMUNE SYSTEM VALIDATION (FAILED)
**Claim:** CI prevents architectural drift.
**Reality:** The CI scanner is a **passive observer with massive blindspots**.

* **Forensic Evidence:** `ci/scripts/scan_forbidden_patterns.py` uses hardcoded whitelist directories (`api/`, `archive/`, `mahoun/ultra_systems/`). Any developer can place destructive, un-governed code inside these directories to silently bypass CI.
* **Regex Blindness:** The scanner uses `r'\b(?:MERGE|CREATE|DELETE|...)\s+[\w\(\$]'`. If a developer dynamically generates a query (e.g., `op = "DE" + "LETE"; query = f"{op} (n)"`) or uses multiline strings breaking the regex spacing, the scanner fails to detect it.

**Verdict:** The immune system can be bypassed trivially via string manipulation or by placing code in quarantined zones.
